# Familiar（灵宠）设计文档

> 仓库代号：`all-in-pet`　产品名：Familiar（中文名：灵宠）
> 状态：P0–P4 已实现（标签 `p0.5`、`p1`、`p2`、`p3`；P4 待打标签），下一步 P5 评测　设计日期：2026-10-25，最近更新：2026-11-05

## 1. 定位

Familiar 是一只住在 macOS 桌面上的宠物，同时也是一个自主运行的 bot。宠物是它的外表；内部有一个 agent，它会记住你、观察你在电脑上做什么、在合适的时候主动找你，并且能在授权范围内替你办事。

- **学习优先**：产品是学习的载体。第一阶段只有作者本人使用，不考虑分发、签名上架、多用户和商业化。
- **只做 macOS**：不考虑跨平台。
- **"all-in" 学习大纲**：
  1. Agent harness：agent loop、工具调用、上下文管理
  2. 记忆：写入、检索、遗忘
  3. 知识库 / RAG
  4. 感知：Computer History
  5. 主动性：调度、触发、打扰预算
  6. 具身表现：宠物窗口、动画、状态
  7. 评测
  8. 本地模型 / 微调（放到最后）
- **借用现成方案**：能用现成库的地方就用现成库，原理通过其他途径学。只有产品的核心（记忆、调度、感知整理）需要自己写，因为没有现成方案同时满足下面所有要求。

## 3. 架构

> 2026-10-26 从 Electron 迁移到 Tauri + TS 进程，详细分工与协议见 `docs/architecture.md`；Electron 版保留在 git 标签 `electron-prototype`。

```
┌──────────── Tauri 壳（Rust，src-tauri/）────────────┐
│ 宠物覆盖层 NSPanel · 聊天面板 NSPanel · 设置窗口       │
│ 点击穿透（AppKit 坐标轮询）· 拖动 · 托盘 / 菜单         │
│ familiar-pet:// 资源协议 · 启动并守护 agent 进程       │
└──────▲ Tauri invoke / event ──────▲ stdio NDJSON ─────┘
       │                             │
 界面（React，src/renderer/）   大脑（TS，Bun，agent/）
 宠物动画 · 胶囊 · 气泡          Agent loop：Vercel AI SDK 7
 聊天面板 · 设置页               Provider 抽象 · 重试 · 权限 · 工具 · 沙箱
                                会话 · 宠物状态机 · 设置（钥匙串）
                                记忆 / 调度 / 知识库 / Computer History（P1 起）
```

- **壳**：Tauri v2（Rust）。只负责窗口和系统集成，不放业务逻辑。宠物窗口用 tauri-nspanel 转成 NSPanel（ScreenSaver 层级、全屏与所有 Spaces 可见）；点击穿透靠 Rust 用 AppKit 坐标轮询鼠标、界面按像素判断后切换。
- **大脑**：独立的 TS 进程，开发时 `bun agent/src/main.ts`，打包时 `bun build --compile` 成单文件放进 `.app`。业务状态的唯一来源。
- **agent loop**：Vercel AI SDK 7，作为库在大脑进程内运行。
- **自己写的部分**：记忆、调度、Computer History 整理、provider 抽象。将来遇到中转站兼容问题，可以在 provider 抽象层里换成 pi-ai。
- **工程**：pnpm + Vite + Tauri CLI，TypeScript strict；Rust 依赖 tauri 2.12、tauri-nspanel 2.1、plugin-opener、plugin-shell。
- **为什么换掉 Electron**：只做 Mac，Electron 的跨平台和单一语言优势用不上，却带来约 300MB 包体和一系列窗口绕路。Tauri 实验验证了三个最大风险（打包后透明不变白、全屏可见、点击穿透）都可行，包体约 12MB（不含约 60MB 的大脑进程）。

## 4. 模型接入

- 统一用"协议 + base_url + API key"接入：
  - 协议：OpenAI 兼容（Chat Completions / Responses）或 Anthropic Messages。
  - base_url：可以填官方地址，也可以填第三方中转站。
  - 用户在设置里自选模型。
- **服务商**（2026-11-01）：设置「模型」页顶部选服务商。OpenAI、Anthropic、DeepSeek、Kimi、Gemini 是预设（地址和协议写死在 `src/shared/presets.ts`，只填 Key，旁边有「获取 Key」链接）；「自定义中转」就是上面的协议 + 地址 + Key。存储不变，当前是哪家由协议加地址反推，所以已有的中转配置不用迁移。
- **ChatGPT 订阅登录**（2026-11-01 提前做，原计划 P7）：协议 `chatgpt`，按官方 Sign in with ChatGPT 的开源本地应用流程实现（`agent/src/agent/chatgpt-auth.ts`）：系统浏览器 OAuth + PKCE，回调监听 `127.0.0.1:1455/auth/callback`，首次用 `dynamic_agent_client` 动态注册并保存发放的 client_id，ID token 用 OpenAI 的 JWKS 验签。只有 refresh token 进钥匙串（钥匙串命令行约 3000 字符以上会写失败），access token 只在内存，账号信息在 `chatgpt-auth.json`（0600），本机 host id 在 `chatgpt-host.json`。刷新串行进行（refresh token 每次轮换）。这条通道只接受流式、`store:false` 的 Responses 请求，不收 temperature、max_output_tokens 等字段，也不收 system 角色消息：`chatgpt-route.ts` 在 fetch 层改写请求，非流式调用（反思、摘要、联网搜索、测试连接）把事件流还原成一个响应。登录卡片有「管理用量」链接。
- **Claude 订阅**：不接。Anthropic 条款不允许第三方应用提供 claude.ai 登录或代管订阅凭证；Max、Ultra、Team 套餐附送的 API 额度用 Console 的 Key 即可（选 Anthropic 预设）。
- 主动性判定这类高频、低价值的调用，可以单独配置一个更便宜的小模型。
- **中转参数**（P0.5）：认证方式（仅 Anthropic 协议：`x-api-key` 或 `Authorization: Bearer`）。自定义请求头和额外请求参数（JSON，浅合并进请求体）大脑仍支持，2026-10-27 起设置页暂不提供入口。
- **网络**：大脑进程读取系统代理设置（`scutil --proxy`）并用于 Bun 的 `fetch`，不另设代理项。

## 5. 权限

| 模式 | 工作目录 | 其他目录 | 联网 | shell |
|---|---|---|---|---|
| 询问 | 每次写入或执行都问 | 按单目录规则 | 问 | 沙箱 + 问 |
| **自动（默认）** | 全部放行 | 按单目录规则（允许 / 询问 / 拒绝） | 放行（2026-11-04 起，命令联网也不再问） | seatbelt 沙箱，只能写工作目录 |
| 完全访问 | 全部放行 | 全部放行 | 放行 | 不加沙箱 |

命令沙箱开关（2026-11-04）：设置「权限」→「命令沙箱」，默认开。关掉后询问和自动模式下命令不加沙箱、像在终端里一样运行（文件工具的权限规则不变）；命令里用 ~、$HOME 或家目录写到硬性禁区（~/.familiar 里除工作目录和可读的四个目录、~/.ssh、钥匙串、浏览器密码文件）时，先弹普通审批卡片，说明里写明会访问哪个位置，确认才运行。这是按命令文本的尽力检查，绕路访问（先 cd 再用相对路径）查不出来。沙箱开着时被拦下的命令，结果末尾会写明是 Familiar 的沙箱拦的、可以在哪里关；命令工具的说明也告诉模型沙箱的边界，不再让用户去系统设置里授权。

授权与规则（2026-11-04）：审批卡有「允许」「全部允许」「拒绝」。「允许」只放行这一次；带目录的请求（工作目录外的读写删、询问模式下的命令联网）和 MCP 工具多一个「全部允许」：目录请求记一条这个目录（含子目录）的「允许」规则，设置「权限 › 目录规则」里立刻能看到、能删；MCP 工具把那个服务器设为允许。命令联网询问记下的规则带「可联网」，之后在那个目录里跑联网命令不再问；普通的允许规则不含联网。询问模式下工作目录里的命令照样每次问。沙箱关闭时的凭据位置询问没有「全部允许」。

任何模式下都成立的规则：

- **硬性禁区永远拒绝**：钥匙串、`~/.ssh`、浏览器的密码库。
- **只读联网**（2026-10-28 定）：`web_search` 和 `fetch_page` 在自动、完全访问模式下直接执行，询问模式下每次问；shell 联网仍按上表。`fetch_page` 只能访问公网地址（拒绝本机、局域网、链路本地，重定向的每一跳都检查），正文和图片都当作不可信资料。
- **git 快照默认开启**：仓库在 `~/.familiar`，用白名单 `.gitignore` 只记录 workspace/、memory/、knowledge/、conversations/、skills/，配置文件永不进 git；每次 agent 操作后自动提交一次，删错了能回滚。可在设置「权限」页关闭；关闭后不再提交，已有 .git 保留，记忆的删除和时间线合并也就没有历史可退（见第 6 节）。工作目录若改到 `~/.familiar` 外，那个目录另建自己的仓库。
- **实现方式**：通过 AI SDK 的 `toolApproval` 函数，把每次工具调用映射到上表。

## 6. 记忆

- **存储**：
  - Markdown 文件存在 `~/.familiar/memory/`，是唯一的真实数据，用户可以直接读和改，git 快照提供版本历史。下面凡是说"留在 git 快照里"的（被替换的旧条目之外的删除、合并掉的时间线原文件），都以快照开着为前提；在「权限」页关掉快照后，这些内容删了就找不回来。
  - SQLite 的 FTS5 和向量只是检索索引，可以随时从 Markdown 重建。
  - 文件格式（P1 定）：每个分类一个文件——`profile.md`、`habits.md`、`topics/<主题>.md`（之后加 `timeline/`、`pending.md`）。一条记忆是一行 `- ` 列表项，行尾 `<!-- familiar {...} -->` 存 id、日期、来源、状态；被替换的旧条目用删除线保留。没有注释的列表项算用户手写、已确认的记忆，文件里的其他内容原样保留。
  - 上下文：已确认的画像和习惯常驻提示词（限约 3000 字），附主题名列表；主题、时间线和待确认由模型用 `recall` 按需检索。经验（2026-11-04）常驻提示词，但有单独的约 800 字额度（取最近确认的），不占画像和习惯的 3000 字，因为它要在动手前就看到，等模型想起来再 `recall` 往往已经晚了；主动发言的判断不带经验。经验和其他推断一样，只从用户亲口纠正或明确要求里抽，先进待确认，用户确认或 3 个不同对话里出现才转正。
  - 检索：SQLite FTS5 的 trigram 分词（中文三字以上），两字词用 LIKE 补；索引放在应用数据目录，记忆文件一有改动（包括手改）就整体重建。设了向量模型（P4）后，`recall` 同时按意思找（「咖啡」能找到「早上喝美式」），向量按文本哈希缓存在 `memory_vectors` 表，重建索引不重复花钱；向量服务出错时只用全文结果。
  - 记忆工具（`remember` / `forget`）不走权限审批，写入后由 git 快照记录；所有写入先过敏感信息过滤（密钥、令牌、密码、卡号、身份证号）。
- **分类**：画像（你是谁、偏好）、时间线（每天发生了什么）、主题（项目、在研究的东西）、习惯（反复出现的流程）、经验（2026-11-04 加：用户纠正过的做法、踩过的坑、该照着做的做法，存 `lessons.md`）。
- **写入**：
  - 用户明确说"记住……"，立即写入。
  - 反思的实现（P1）：对话安静 30 分钟或切到别的对话后，用「后台小模型」（设置里可选，留空用主模型）读这段对话里新增的部分，输出候选记忆和一句时间线摘要（当天已有的时间线一并给它，同一件事换段对话再问不重复记）；候选只进 `pending.md`。开着 Computer History 时，对话整理只提取判断，不写时间线：时间线由感知按时段的整理来写，并把同一时段的对话一起读进去；关着时才写这一句摘要。写进时间线的条目记着来源对话的 id，时间线页可以从条目打开原对话。每 5 分钟检查一次，只看最近 3 天的对话，每次最多 3 个。设置「时间线」和「待确认」页的「现在整理」同时整理对话和电脑活动。
  - 转正：用户在「记忆 › 待确认」点「记下」（可先「改」；「不对」丢掉；每条写明确认后记到哪里、依据什么），或同一判断在 3 个不同对话里出现（反思时用 sameAs 指向已有条目）。用户的确认、纠正、否定记进应用数据目录的 `evals/memory-feedback.jsonl`，作为评测数据。
  - 对话整理和 Computer History 的按时段摘要，各自抽取出候选记忆，都只进待确认。
  - 推断出来的偏好先进"待确认"区，带置信度；用户确认，或同样的情况被反复观察到，才转正。"待确认"区就是面板里的"它对我的判断"，用户可以纠正。
- **遗忘**：
  - 时间线逐级压缩：按天记录，满一周合成周记，满一个月合成月记。周按 ISO 周算，周和月的归属看那一周的周四（所以 9 月 28 日那周算进 10 月）；条目少时直接拼接，多了才用后台模型概括；原文件从工作目录删掉，留在 git 快照里。合并出的每一行都带着被合并条目的来源对话 id（包括更早合并留下的），所以合并后仍能回到原对话，时间线页打开其中最近的一个。
  - 偏好被推翻时，用新的标记替换旧的，不直接删除，保留历史。
  - 用户可以删除任意一条。删除画像、习惯或主题里的一条后，「记忆」页会列出时间线里仍在复述它的条目（两字片段重合一半以上），提供「一并删除」；对它说「忘掉……」时，`forget` 也会返回这些条目让它一起删。刚删掉的内容在进程内记 24 小时（不落盘），这期间反思不会再把它写回待确认或时间线。
  - 敏感信息永远不写入。

## 7. Computer History（感知）

参考 ChatGPT Computer History 现行方案，并补上它的两个短板：记忆不加密、没有采集前的敏感信息过滤。

- **采集**：
  - 只采辅助功能事件和文本：前台应用、窗口标题、浏览器 URL 和页面标题、空闲状态、可读到的文本上下文。
  - 不截图，不申请屏幕录制权限，不碰摄像头和麦克风。
  - 只在有变化时采集（切换应用、点击、停止输入），不做定时采样。
- **默认关闭，开启后采集所有应用**：不预填任何排除，用户自己排除应用和网站；浏览器隐私模式一律排除。
- **两层存储**：
  - 原始事件：在本地加密缓冲，最多保留 48 小时，密钥放在钥匙串里。
  - 长期记忆：定时摘要成时间线和候选记忆。
  - 两层可以分别删除。
- **敏感信息过滤**：采集时就丢弃密码框、卡号这类内容。
- **出机说明**：摘要用的是用户选的模型，所以过滤后的文本会离开本机。设置里要写明这一点；某个应用可以标记成"只采集，不上传摘要"。
- **控制面板**（先于感知功能上线）：
  - 一键暂停。
  - 排除的应用、只留本机的应用、排除的网站。
  - 清除最近 10 分钟、1 小时、1 天或全部记录。
  - 查看和删除记忆。
- **安全**：采集来的内容一律当作不可信输入，防止提示注入。
- **签名**：从 P2 起用固定证书签名（本机已有的 Apple Development 证书，`tauri.conf.json` 的 `signingIdentity`，代替原定的自签证书）。ad-hoc 签名每次重新构建都会变，辅助功能授权会悄悄失效，系统设置里却仍显示已勾选。
- **实现（P2，2026-10-29）**：
  - 采集程序 `sensor/main.swift`（`familiar-sensor`）是 agent 的子进程，stdin 收配置、stdout 逐行出事件。辅助功能权限记在负责进程上：打包后是 Familiar.app，开发时是跑 `pnpm dev` 的终端。
  - 事件：切换应用、未排除应用的 AXObserver（聚焦窗口、标题、焦点元素变化；值变化停止输入 2 秒后读一次）、空闲 5 分钟。只看有 Dock 图标的普通应用，登录窗口、通知、密码弹窗、台前调度、辅助进程这类系统进程不记。未排除应用读窗口标题、`AXWebArea` 的网址、焦点元素的选中文字或光标附近最多 2000 字；密码框不读；标题像隐私窗口的只记应用。Chromium / Electron 应用先设 `AXManualAccessibility`。
  - agent 入库前过滤（`agent/src/perception/activity.ts`）：排除列表里的应用什么都不留，连应用名也不记，只在时间上留个空档；排除网站只留应用名；网址只留到路径（查询参数、`#` 后面和账号密码都去掉，路径里像密钥的段换成 `…`），因为令牌和验证码都在参数里，搜了什么页面标题已经写着；标题和正文被敏感信息过滤命中就整段丢掉。
  - 原始事件按小时存 `~/.familiar/perception/*.enc`，每行一条 AES-256-GCM 密文，密钥在钥匙串（account `perception-buffer-key`）；48 小时自动删除；「全部清除」同时换密钥。这个目录不进 git，模型工具和沙箱都读不到。
  - 清除最近一段时间：原始事件删掉，和这段时间有重叠的历史条目整条删掉（它的摘要里写着被清除的那几分钟）；摘要进度退回到被删条目的开头，那几个时段剩下的事件会重新摘要。
  - 摘要：按设置的间隔（默认 30 分钟），先在本地把事件合成"活动片段"，「只留本机」的应用不进模型输入；同一时段内的对话一并读进去，后台小模型每个时段写一条历史（标题、一段话、用到的应用和来源对话 id）和最多 3 条候选，候选只进待确认、置信度不超过 0.7；摘要窗口不跨午夜。
  - 控制面板在设置「感知」分组：「时间线」放感知整理和对话整理写出的条目（按天分组，有时间、标题和应用图标，对话来源的条目带「打开对话」）；「采集设置」管开关、暂停、应用和网站、清除记录；「原始记录」看加密缓冲里的事件。托盘有「暂停感知 / 继续感知」。「记忆」分组只放提炼出的画像、习惯、主题和待确认（2026-10-31 调整：时间线是发生过什么，归感知；记忆只放从中提炼出的判断）。

## 8. 主动性

- **触发源**：
  1. 事件：在同一个问题上卡了很久、连续工作太久没休息、离开后回来、每天第一次打开电脑。
  2. 记忆：跟进用户之前说过的事。
  3. 提醒到期。
  4. 心跳：定时检查一次有没有值得说的事。
- **判定流程**：先用便宜的规则筛选，有候选事件时才用小模型判断值不值得打扰，不在每次心跳时都调用模型。
- **打扰预算**（默认值，可在设置里改）：
  - 次数和间隔由「说话频率」档位和用户的反应决定（见本节「实现」里的「频率」）。
  - 免打扰时段、全屏、会议中保持静默。会议判断用前台应用（Zoom、Teams、飞书会议）、麦克风是否被占用；日历是可选信号。
  - 用户点"忽略"或"别烦我"会让它自动收敛，回复会提高权重。
  - 以后用评测数据来调这些参数。
- **透明度**：每次主动发言都附带"为什么现在说"的依据。
- **情绪和困扰**：只从行为信号和聊天文本判断，推断结果放进"它对我的判断"，可以纠正。
- **提醒**：只用自己维护的调度，不写系统的提醒事项和日历。
- **日历**：做成设置项，默认关闭；打开后也只读，永远不写。
- **实现（P3，2026-11-01）**：代码在 `agent/src/proactive/`。
  - 默认：主动发言打开，说话频率「自动」，免打扰时段默认关（打开后默认 23:00–08:00）。设置窗口「主动」页可改频率档位（自动 / 安静 / 适中 / 话多），也能关掉单个触发。2026-11-01 第二版：去掉了「每天最多几次」「间隔几分钟」两个数字设置，频率由档位和你的反应决定。
  - 提醒：存在 `~/.familiar/reminders.md`，一行一条（`- [ ] 日期 时间 内容`），可以直接编辑。模型用 `remind` / `list_reminders` / `cancel_reminder`，系统提示里带上了当前时间。待办（2026-11-04）：不写日期时间的行（`- [ ] 买牛奶`）就是待办，模型用 `add_todo` 记，排在有时间的提醒后面；它没有到期时间，不会自己弹气泡，也不占打扰预算，写坏的日期仍然跳过、不会误判成待办。`remind` 的 `follow_up=true` 是小黑自己记下的跟进（比如面试之后问问），算主动发言、占预算。
  - 调度：每分钟看一次。依次检查：正在对话、胶囊或面板开着、你不在电脑前（键鼠空闲 2 分钟以上），满足任一条就先不说；全屏或在开会（会议应用在前台、麦克风被占用，由采集程序 `--context` 现查，不记录）也不说。
  - 到期的提醒总会说，只有免打扰时段内等到时段结束；你不在时等你回来，一分钟内弹出。
  - 小黑自己的想法分两类，都先过频率，再等一个打断代价低的时刻（停下来 20 秒以上、在一个应用里待了 10 分钟后刚换应用、离开 5 分钟后刚回来；每天第一次和离开半小时回来本身就算）才说：
    - 内容：感知每写完一段摘要（刚结束的那段，不含补跑的旧时段），把摘要连同记忆、最近说过的话交给后台小模型，问有没有能结合记忆或之前聊过的事给出具体帮助的一句话。有就放进待说队列，40 分钟内等到合适时刻说，过期作废。每段摘要最多多一次小模型调用，频率已用完时不调。
    - 关心：规则从原始记录里找（每天第一次、离开 30 分钟后回来、连续 90 分钟、23 点后还在用），再让小模型判断说不说、写出那句话。到期的跟进也走这条。每个触发每次只问一次，模型说不说都算问过。
    - 第一版的「40 分钟里大多停在同一个窗口」规则删掉了，由内容这一类按实际在做的事判断。
  - 判断材料里的提醒（2026-11-04）：交给小模型的上下文除了记忆、相处和最近说过的话，还有未来 24 小时内到期的提醒和跟进（最多 8 条，标今天或明天和时间），这样「他提过的截止时间快到了」才有依据。每天第一次开电脑那次判断再带最多 5 条没有时间的待办。不增加模型调用次数。
  - 气泡：下面一行灰字写依据，三个按钮。好：这句话进入对话并打开面板。稍后：提醒 10 分钟后再来。别烦我：当天剩下的时间不再主动说（提醒照常），可在设置页「恢复」。用户自己设的提醒（2026-11-02）只有「知道了」（关掉，不打开面板）和「10 分钟后」，没有「别烦我」；猫耳去掉了。没点（2026-11-05 改）：倒计时从气泡出现后你第一次动键鼠开始算，提醒 10 分钟、自己的想法 45 秒，到时收起记为「没理」；气泡出现后 10 分钟里一直没有键鼠输入，就收起记为「没看到」。之前倒计时一弹出就开始，而「停下来了」这个时机要求空闲 20 秒以上，人起身离开时弹出的话也被记成「没理」。宠物窗口在气泡显示期间加高，放得下依据和按钮；气泡显示期间宠物保持「等你回应」的动作，消失后恢复。
  - 没看到的话（2026-11-05）：宠物头顶右侧挂一个草绿小圆点，点一下重新弹出最新的那句；菜单栏面板也列出最新一句（「刚才想说」），点了同样重新弹出。重新弹出后照常处理。自己的想法 40 分钟后过期，你设的提醒保留到当天结束。
  - 提示音（2026-11-05 记下，暂不做）：以后加一个可选的气泡提示音，默认关闭。
  - 频率：安静每天 2 次、隔 120 分钟；适中 4 次、60 分钟；话多 6 次、30 分钟。自动按近 7 天你主动找它聊的条数起步（少于 10 条：3 次、75 分钟；10 条以上按适中；40 条以上按话多），近一周它的话你回应过半就多给一次、间隔缩短，回应不到两成就少一次、间隔拉长。任何档位下，近 3 天每次「别烦我」少 2 次、「没理」少 1 次、「回应了」加 1 次，「没看到」不算回应，不扣也不进回应率（但仍占当天的次数）；自动档已经按回应率调过时（近一周至少 3 次回应记录），近 3 天只再算「别烦我」，同一句「没理」不扣两次（2026-11-04）。硬上限：每天最多 8 次，间隔 20 到 180 分钟，至少 1 次。所有反应记进 `evals/proactive-feedback.jsonl`，2026-11-05 起每条带气泡出现和结束时的键鼠空闲秒数（`idleAtShow`、`idleAtEnd`）。
  - 精力和亲密度（简单版）：精力看钟点，深夜 2 分钟没动就睡；亲密度看和你聊过几天（`proactive.json` 里按天计数）。两者写进给模型的「相处」一行，影响语气。
  - 评测：`pnpm eval` 加了 7 条主动发言用例（该说、跟进、刚说过不再说、不提观察、在做的事和记忆有关时说、日常工作不打扰、今天有快到的提醒时提一句）。

## 9. 宠物

### 状态模型

| 维度 | 取值 | 作用 |
|---|---|---|
| 在做什么 | 待机、倾听、思考、干活、说话、需要你、睡觉 | 决定播放哪段动画 |
| 心情 | 开心、担心、困、好奇、平静 | 影响表情和气泡语气；面板里能看到为什么是这个心情 |
| 感知指示（必须有） | 采集中、暂停、只听聊天 | 一眼看出它有没有在看你，比如暂停时戴眼罩 |
| 精力 | 随作息时间变化 | 深夜犯困、催你睡觉；影响主动频率 |
| 亲密度 | 随互动次数增长 | 影响称呼、语气和主动程度 |
| 身体交互 | 被拖动、被摸头、被戳、沿屏幕边缘走、坐在窗口顶上、贴边藏起并从边缘探头 | 只在壳里本地处理，不经过大脑 |

显示优先级："需要你"最高，其次是进行中的对话或任务，最后是空闲时的心情表现。宠物旁边配一个活动托盘，列出正在跑的任务和待处理的提醒。ChatGPT Pets 只作参考，不照抄。

精力和亲密度先做简单版：精力看作息时间，亲密度看互动次数，后面再细化。

贴边藏起（2026-10-27 记下，暂不做）：把宠物拖到屏幕边缘时缩进去、只露一点，鼠标靠近或有事时探出来；"根据用户当前状态自己藏 / 自己扒出来"依赖 P3 的完整状态模型和感知，探头动作要在 P6 补进图集。手动藏起可以在 P3 前单独做。

动作快慢（P0.5）：设置里分慢 / 正常 / 快（帧率 ×0.6 / ×1 / ×1.5），作用于宠物自己的动画；被拖动时的跑动动画跟手，不受影响。

大小与快慢（2026-11-03）：设置「宠物」页的大小和动作快慢各有三个预设按钮（小 / 中 / 大 = 0.5 / 0.73 / 0.95；慢 / 正常 / 快 = 0.6× / 1× / 1.5×）加一根滑杆，自己拖也行。范围：大小 0.4–1.3，快慢 0.5×–2×。设置里存数值（pet.scale、pet.rate），旧设置里的 small / medium / large、slow / normal / fast 读取时自动换算。滑杆数值正好等于某个预设时，那个按钮亮起。菜单栏的大小菜单保留三档，数值不是这三档时都不打勾。

### 界面（P0.5 定稿，稿子在 `docs/ui/`）

- **视觉方向**（2026-10-31 改）：现代工具风（参考 Linear、Raycast），不再模仿系统设置：暖中性灰底、细描边卡片、单色线性图标、自有的紫蓝强调色（不跟随系统强调色），跟随深浅色。设置窗口侧边栏是可展开的树（记忆、感知、扩展有子页），页内不放大段说明，必要的提示放进占位符或悬停提示。小黑的草绿只用在属于它的元素上（感知点、气泡尾点）。

## 11. 知识库

- 与记忆分离：记忆是关于用户的，大部分由它自己写；知识库是关于文档的，由用户提供。
- 收录范围（P4，2026-11-05）：
  - 用户在设置「知识库」页添加的文件夹（Obsidian 库、项目文档等，用系统的选择文件夹窗口添加）：只读，FSEvents 递归监听，改动 2 秒后增量更新；另外每 15 分钟补一次，补上睡眠或外接盘离线时漏掉的。`~/.familiar` 里面的文件夹和整个家目录不能添加。加进来的文件夹不受「目录规则」限制，添加本身就算授权。
  - `~/.familiar/knowledge/`，固定收录、不能移除。
  - 用户在聊天里让它"存下来"的网页：`save_page` 抓正文（最多 20 万字），存成 `knowledge/web/<标题>.md`，开头记来源网址和保存时间；同一网址再存会覆盖原文件。跟着 git 快照走。权限同 `fetch_page`（询问模式要问）。
- 格式：md、txt 等文本，pdf（`unpdf` 抽文字，按页；扫描件读不出字会列为「读不了」），常见代码文件。跳过隐藏文件夹、`node_modules` / `dist` / `build` 等，文本超过 2 MB、PDF 超过 50 MB 的不收，每个文件夹最多 5000 个文件（超出时页面会提示）。PDF 里常见的康熙部首字形（⼝ U+2F1D 之类）抽出来后换成常用字，否则搜不到。
- 切块：约 800 字一块；Markdown 先按标题切，再按空行，每块记着标题路径；PDF 每块记页码，文本记行号。紧跟在另一个标题后面的标题不单独成块。
- 与记忆共用同一个 SQLite 文件（`memory-index.sqlite`），但分表存储（`kfiles`、`kchunks`、`kchunks_fts`、`knowledge_vectors`）。和记忆索引整体重建不同，知识库按文件增量更新（看大小和修改时间），因为一个库可能有几千个文件。
- 检索：全文（FTS5 trigram + 两字词 LIKE，同记忆）和向量结果按名次融合（RRF）。向量在设置「模型 › 向量」选来源：「本机」或「在线服务」。在线服务是单独配的 OpenAI 兼容 embedding 模型（模型名、地址、Key，Key 存钥匙串的 `embedding-api-key`），没配就只用全文；ChatGPT 订阅通道调不了 embedding，所以和对话模型分开配。
- 本机向量（2026-11-05，用户选定自带 llama.cpp，而不是依赖 Ollama）：`.app` 里带一个 llama.cpp 的 `llama-server`（`pnpm llama:build` 从固定版本 v0.9.0 的源码编成静态单文件，Metal shader 内嵌，约 20 MB；预编译包是动态链接的，放进 `.app` 要改 rpath，所以自己编）。模型只提供 Qwen3-Embedding-0.6B（Q8，约 610 MB），在设置里点「下载」从 Hugging Face 下到 `~/.familiar/models/`（不进 git 快照），可暂停、断点续传，下完核对 sha256。agent 第一次要向量时才启动 llama-server（只听 127.0.0.1，随机端口，`--pooling last`），闲置 10 分钟停掉；agent 被强杀留下的进程在下次启动时按 pid 文件清掉，清之前确认那个 pid 还是 llama-server。查询前面加 Qwen3 官方建议的英文检索指令，文档原样嵌入。没下载模型时和没配在线模型一样，只用全文。向量相似度只保留和最高分相差 0.15 以内、且不低于 0.2 的结果，因为各家模型的分数尺度不同。
- 向量不用 sqlite-vec：Bun 在 macOS 上用系统 SQLite，不能加载扩展，要用就得往 `.app` 里带一个自己的 libsqlite3。改成把归一化的向量存成 BLOB、在 JS 里算点积；个人规模（几万块以内）够快。
- 出机：在线服务会把文件内容发给向量模型的服务商，页面上写明；本机模型不出机。命中敏感信息过滤（密钥、密码等）的块不发去向量化，只能被全文找到。
- 模型怎么用（用户 2026-11-05 选定按需调用，不每轮自动注入）：`search_knowledge` 返回片段和出处（文件、标题、行号或页码），`read_knowledge` 读一个已收录文件的一段（文本按行，PDF 按页，只能读索引里有的文件），`save_page` 存网页。三个工具都不占提示词，系统提示里只有一段说明和已添加的文件夹名。
- 设置页「知识库」：每个文件夹的文件数、向量进度、读不了的文件及原因，可打开、移除、重新索引。

## 13. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 自己从零写 agent loop | 用户选择借用现成方案，原理另外学 |
| 把 OpenClaw 整个当后端 | 是重型网关服务，默认拥有全部权限，Claude 订阅已不覆盖它；只作为记忆和心跳设计的参考 |
| 调起 Codex / Claude Code CLI 子进程来用订阅额度 | 架构别扭；Claude 订阅接入有封号风险；改走 API key 加中转站 |
| Mastra 作主框架 | 记忆以 LibSQL 为准，与"Markdown 为准"冲突；官方 Electron 方案要起独立服务，不能嵌进主进程 |
| Electron（P0–P0.5 曾使用） | 只做 Mac 时跨平台与单一语言的优势用不上；包体约 300MB；透明穿透、毛玻璃、原生控件都要绕路。2026-10-26 迁到 Tauri，旧版见标签 `electron-prototype` |
| Swift 原生壳 | 窗口与控件最原生，但界面要用 SwiftUI 全部重写，还要两种语言加一层进程间通信，偏离"学 AI"的重点；Tauri 能复用现有 React 界面，实验已验证窗口能力可行 |
| screenpipe 作采集层 | 许可证已改为商业许可；只参考它"有变化才采集"的事件驱动设计 |
| 截图加 OCR 的感知方式 | 要申请屏幕录制权限、数据量大、隐私负担重；ChatGPT 也从这条路（Chronicle）退了出来 |

## 14. 已知风险与待验证

- AI SDK 大版本迭代快（一年多从 v5 出到 v7），只支持 ESM，要求 Node 22 及以上。
- 中转站的协议"方言"（reasoning 字段、`max_tokens` 字段名等）可能需要自己写 middleware 适配。
- 点击穿透靠轮询（16ms）加网页判断，鼠标瞬移后立刻点击可能落到下层窗口；真人操作一般不受影响。
- 各浏览器的 URL 能不能通过 AX 树读到，要实测；读不到的改用 AppleScript。
